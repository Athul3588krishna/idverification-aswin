2. DATABASE DESIGN / COLLECTIONS

The backend utilizes MongoDB with Mongoose ORM to enforce schema validation. The primary collections and their attributes are detailed below:

2.1 Collection: users ( User.js )

Stores user profiles for Students, Security Staff (Verifiers), and Administrators.

Field Type Constraints Description
_id ObjectId Primary Key, Auto Unique user identifier
name String Required Full name of the user
email String Required, Unique, Lowercase Email address for login
password String Required, Min length 6 Hashed password (Bcrypt)
role String Enum: ['admin', 'security_staff', 'student'] User access role
phone String Match: 10 digits, Default: null Contact phone number
studentProfile Object Populated if role === 'student' Student exam details
isActive Boolean Default: true Account active status
createdBy ObjectId Ref: 'User', Default: null Admin who created account

4. USER STORIES

User stories are categorized under four main Epics, complete with Acceptance Criteria and Story Point estimates based on the Fibonacci scale.

Epic 1: Identity & Access Management (IAM)
📖 User Story 1.1: Security Staff & Admin Registration with Email OTP

As a Security Officer / Administrator,

I want to register an account using my email and verify via a 6-digit OTP,

So that only authorized gate personnel can log into the verification portal.

Acceptance Criteria:

  • Nodemailer dispatches a 6-digit OTP code with 5-minute TTL expiration.
  • Passwords are pre-hashed using Bcrypt (12 salt rounds) prior to storage.
  • Returns HTTP 201 Created upon successful OTP validation.

Story Estimate: 3 SP

📖 User Story 1.2: Unified JWT Authentication & Role Control

As a User (Student / Admin / Security Staff),

I want to authenticate using my registered credentials,

So that I can receive a secure JSON Web Token and access role-restricted pages.

Acceptance Criteria:

  • Returns JWT token containing user ID and role payload on valid match.
  • Invalid credentials return HTTP 401 Unauthorized response.
  • Frontend stores JWT in localStorage and auto-attaches via Axios headers.

Story Estimate: 3 SP

Epic 2: Student Master Data & ID Management (SMD)
📖 User Story 2.1: Student Profile Creation & ID Card Photo Upload

As an Administrator,

I want to add candidate details and upload their reference ID card photo,

So that candidate records exist for gate matching during examinations.

Acceptance Criteria:

  • Multer middleware handles image upload and saves path to student profile.
  • Enforces unique roll number constraint in MongoDB database.

Story Estimate: 5 SP

📖 User Story 2.2: Bulk Student Registration via CSV Import

As an Administrator,

I want to upload a CSV file containing candidate records,

So that I can onboard thousands of exam candidates simultaneously.

Acceptance Criteria:

  • Parses CSV rows into structured JSON objects and batch-inserts to MongoDB.
  • Returns clear breakdown of successfully imported versus duplicate records.

Story Estimate: 4 SP

Epic 3: OCR Gate Verification & Identity Matching (OIV)
📖 User Story 3.1: Live Camera Scan & Image Capture UI

As a Security Staff Verifier,

I want to capture or upload a candidate's ID card photo at the entrance gate,

So that the system can process the image for text recognition.

Acceptance Criteria:

  • Webcam integration allows instantaneous frame capture or drag-drop upload.
  • Visual loading overlay displays scan progress to the officer.

Story Estimate: 5 SP

📖 User Story 3.2: Tesseract OCR Engine Text Extraction & Matching

As a Security Staff Verifier,

I want Tesseract OCR to extract roll numbers and candidate names automatically,

So that manual keying errors are eliminated during high-volume entry hours.

Acceptance Criteria:

  • Regex normalizes extracted text to isolate candidate roll numbers.
  • Queries MongoDB for matching student profile and computes match score.

Story Estimate: 5 SP

Epic 4: Security Dashboard & Real-Time Analytics (SDA)
📖 User Story 4.1: Real-Time Socket.io Security Scan Feed

As an Administrator,

I want to view live gate scan results as they occur across all entry gates,

So that I can immediately spot fraudulent attempts or impersonation alerts.

Acceptance Criteria:

  • Socket.io pushes scan events instantly to the central admin dashboard.
  • Displays green APPROVED and red REJECTED badges in real time.

Story Estimate: 5 SP
